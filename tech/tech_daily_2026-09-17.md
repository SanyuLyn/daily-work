**摘要**：文章梳理 Flutter 3.47 最具影响力的一项变更：material_ui 与 cupertino_ui 独立包发布 1.0，设计系统正式从核心 SDK 解耦，迁移可用 `dart fix --apply --code=migrate_design_widgets` 自动完成，而 SDK 内置的旧设计库将在 11 月的秋季稳定版中正式废弃。另外两项重点是桌面端 Impeller 默认替换 Skia（macOS/Windows/Linux 三端生效），以及 Apple 平台最低版本抬升（iOS 13→15、macOS 10.15→12）并强制 UIKit 应用采用 UIScene 生命周期，为 Xcode 27 / iOS 27 铺路。解耦的直接收益是设计库可独立发版——Slider 的一个 bug 修复不必再等三个月的 SDK 班车。文章对存量项目的建议是观望约两个月再升级，等核心功能收敛、三方生态跟上。

### [Flutter UI 设计库解耦重构进度，官方解答未来如何适配](https://zhuanlan.zhihu.com/p/1986399159603991382)
**摘要**：文章从官方视角解释了设计库解耦这场大重构的动因与代价。动因是 Material 3 Expressive、Liquid Glass 等新风格让 Framework 层的 UI 适配成本急剧上升，而 Framework 的发版节奏根本跟不上设计规范的迭代速度。解耦后核心框架只保留基础 Widget，具体设计风格变成可选包，开发者可以自行锁定风格包版本，Framework 层的 UI 破坏性变更会显著减少。代价主要落在 Plugin 作者身上：UI 实现要考虑用户用的是哪个版本的风格包，潜在的版本冲突需要额外处理。值得注意的一点是，在解耦完成前官方会暂停引入新的大型设计更新（如 Liquid Glass），以降低迁移难度——这解释了为什么这段时间 Flutter 在视觉层面显得"没动静"。

### [回顾 Flutter Flight Plans，关于 Flutter 的现状和官方热门问题解答](https://zhuanlan.zhihu.com/p/1976187085061907287)

**摘要**：文章梳理了 Android 17（targetSdk 37）对开发者影响最直接的几项变更。最大的一项是大屏适配彻底强制化：在 sw > 600 dp 的设备上，开发者不能再通过代码或配置锁定横竖屏、限制宽高比，系统会让应用随窗口大小自由伸缩。第二项是短信 OTP 访问权限大幅收紧，对大多数应用而言含 OTP 的短信要 3 小时后才能读取到，依赖短信自动填充验证码的登录流程需要重新设计。相机方向也是高频踩坑点——大屏设备上的预览变形通常源于代码里硬编码了屏幕方向与传感器方向的关系，官方推荐改用 PreviewView，由它自动处理传感器方向、设备旋转与缩放。时间线上，Google Play 强制 targetSdk 37 的截止日期是 2027 年 8 月，文章建议有相机、短信 OTP、局域网设备连接功能的应用现在就用 Android 17 Beta 开始测。

### [Android 不再阻止开发者和高阶用户安装未验证应用，这一政策调整有哪些意义？](https://www.zhihu.com/question/1972267168323298093)

### [安卓应用侧载新规：专为高级用户设计的「高级流程」](https://zhuanlan.zhihu.com/p/2018301248428852406)
