## Flutter

### [iPhone Duo 适配详解，需要改变的不止是布局模型](https://zhuanlan.zhihu.com/p/2081732020691117995)
**摘要**：围绕苹果首款折叠屏 iPhone Duo 的适配展开。苹果官方口径是「大部分 App 只要正确支持 resizing、并使用系统导航与布局组件即可自动适配」，但对 Flutter 这类自绘 UI 框架并非如此简单。App 需要同时处理外屏、内屏、半折（half-open）与 Split View 等多种形态，窗口尺寸和可用区域会动态变化。文章指出关键改造点在于放弃以 portrait / landscapeLeft 等方向枚举判断页面结构的老写法，转向基于 Size Class、Trait Collection 与真实窗口尺寸的响应式布局。Flutter 侧目前仍在补齐能力，社区已出现 iphone_duo_layout 等插件，官方仓库也有 MediaQuery.displayFeatures 在 iOS 上填充铰链信息、支持半折状态与 ArrangementView 的多个 issue 在推进。

### [iPhone Duo 点燃跨端大战！React Native 和「新 Flutter」开撕！](https://zhuanlan.zhihu.com/p/2081755123412423404)
**摘要**：折叠屏 iPhone 的发布意外成为跨端框架竞争的新战场。文章记录了 iPhone Duo 发布后各阵营的抢跑：Expo 团队迅速跟进宣布支持，React Native 生态借势造势；DartNative 作者随后发帖回应，双方围绕「谁能第一时间吃下折叠屏红利」展开争论。核心分歧在于折叠形态对渲染与布局体系的要求——原生控件复用度高的方案迁移成本低，而自绘引擎需要自行实现铰链感知、双栏布局与折叠态生命周期。文章认为这轮争论的实质，是新硬件形态重新拉开了各框架「贴近系统能力」的差距，跨端方案的选型逻辑可能因此被重新洗牌。

### [Flutter 版本选择指南：3.47 压哨发布，9 月大限只剩一周](https://zhuanlan.zhihu.com/p/2075239430453998791)
**摘要**：面向团队的 Flutter 版本选型指南。3.47 的三大变化为：设计系统拆包（推出生产就绪的 material_ui 与 cupertino_ui 1.0，SDK 内置版本在 3.47 中仍保留、升级不会破坏现有应用，但将于 11 月秋季版正式废弃）；桌面端 Impeller 转正，成为 macOS、Windows、Linux 三端默认渲染器，官方敢全量默认说明对质量有信心；Widget Previews 正式转正。文章重点提示所谓「9 月大限」：iOS 27 SDK 强制所有 UIKit 应用采用 UIScene 生命周期，用 Xcode 27 构建但未迁移的应用会在启动时直接失败，Flutter CLI 对多数应用可在构建时自动完成该迁移。

### [Flutter 3.47 更新要点：Material 正式分家，老项目先别急着更新](https://zhuanlan.zhihu.com/p/2071985919243065015)
**摘要**：聚焦 3.47 中 Material 库从 SDK 拆出这一破坏性较大的架构调整。material_ui / cupertino_ui 独立成包后，设计系统可以脱离 Flutter SDK 发版节奏独立迭代，修 bug 和加特性不必再等季度版本，这对长期演进是明确利好。但文章给出偏保守的落地建议：存量项目不宜在 3.47 立即迁移，SDK 内置版本尚未移除，留有缓冲期；应先评估三方 UI 组件库对新包的适配进度，避免出现 SDK 内置 Material 与独立包混用导致的类型冲突和主题不一致。建议把迁移窗口放在 11 月秋季版废弃节点之前完成。

### [2026 AI 时代下，Flutter 和 Dart 的机遇和未来发展，AI 一体化](https://zhuanlan.zhihu.com/p/2023038328287634312)
**摘要**：梳理 Flutter / Dart 在 AI 时代的定位转向。文章认为 Flutter 已经走完「UI + Agent + Fullstack AI 一体化」的路径铺设，官方与社区陆续补齐了 Flutter MCP（让 Agent 接入 Flutter 工具链）、Plugin Assets AI、Flutter Skills、GenUI（生成式 UI）以及 GenKit-Dart（Dart 侧的 AI 应用开发框架）等一整套能力。其判断是：Flutter 的价值不再只是「一套代码多端运行」的 UI 层，而是有机会成为 AI 应用的端侧承载框架——由大模型生成界面、Dart 全栈承接业务与 Agent 编排。配合 2026 Roadmap 中 Wasm 成为 Flutter Web 默认方案、桌面多窗口能力完善，整体生态仍在扩张。

### [Android 17 新适配要求，各大权限进一步收紧，适配难度提升](https://zhuanlan.zhihu.com/p/2020865242960277920)
**摘要**：逐项拆解 Android 17 的权限收紧，定位其为「系统级控制模型重构阶段」。位置权限引入单次授权与动态粗略定位算法，新增系统提供的「位置按键」用于单次精确定位授权，需声明 USE_LOCATION_BUTTON。短信权限大幅收紧含 OTP 的短信访问，对多数 App 而言 OTP 短信需在 3 小时后才可读取，文章建议有验证码读取需求的应用迁移到 SMS Retriever API 或 SMS User Consent API。NPU 访问在 targetSdk 37 后必须在 Manifest 声明 FEATURE_NEURAL_PROCESSING_UNIT，否则调用被拦截。联系人方面建议用联系人选择器替代整体 READ_CONTACTS 权限。

### [Android 17 正式版发布，全新 AI 和各种破坏性更新](https://zhuanlan.zhihu.com/p/2050523911419326680)
**摘要**：Android 17 正式版的整体盘点，主线是 AI 能力下沉与一批破坏性变更并行。系统层面把 AI 能力做成可被应用调用的基础设施，应用可将核心能力以「接口」形式暴露给 Gemini 助手，由系统侧完成跨应用的任务编排。破坏性更新集中在权限模型、后台行为限制与大屏适配要求上，不少存量应用在不改代码的情况下会直接出现行为异常或崩溃。文章的建议是把 targetSdk 升级当成一轮完整回归测试来做，优先排查定位、短信、通知与后台任务四类高频踩坑点，而非临近 Google Play 截止期再突击适配。

### [Google I/O 2026 | Android 全面进化：从操作系统到「智能中枢」](https://zhuanlan.zhihu.com/p/2042170777936607180)
**摘要**：从 Google I/O 2026 的发布内容总结 Android 的定位变化：从「应用启动器」转向能跨应用编排任务的「智能中枢」。UI 层官宣进入 Compose First 时代，Compose 成为标准方案，View 体系进入维护状态。智能能力方面，新的智能 Autofill 可读取上下文，例如从相册或 Gmail 附件中提取护照号自动填入表单；应用可把核心能力暴露给 Gemini 调用。多设备方面，Android 17 要求大屏全屏适配，开发者需使用 Compose Adaptive 库，不再允许大屏应用敷衍了事。工具链上 Google 推出 Android CLI 支持第三方 AI Agent，Claude Code 等 Agent 可与 Android Studio 核心功能交互。

### [2026 年了，为什么我建议你放弃「纯原生」开发？](https://zhuanlan.zhihu.com/p/2005597393710753297)
**摘要**：一篇关于移动开发技能结构的观点文。作者认为在 AI 时代与跨端方案成熟的双重挤压下，坚持纯原生的单平台技能栈性价比正在快速下降：一方面 UI 层的重复劳动大量被跨端框架和生成式工具吸收，另一方面业务侧对「一人多端」的要求越来越普遍。文章同时提到腾讯宣布开源基于 Kotlin 的 Kuikly 跨端框架，覆盖 Android、iOS、H5、小程序与 PC 多端，进一步压缩了纯原生的相对优势。结论并非否定原生能力的价值——性能优化、系统能力对接仍需原生功底——而是建议把原生作为深度底座，在其上叠加跨端与 AI 工程能力。
