### [如何评价谷歌将对开发者强制身份认证，否则 APK 无法被侧载安装？](https://www.zhihu.com/question/1943682334009320841)

### [Google 开始正式强制 Android 适配 16K Page Size，你准备好了吗？](https://zhuanlan.zhihu.com/p/1904196757702834168)
**摘要**：文章聚焦 16 KB 内存页大小这一底层适配要求。Google 的时间线是自 2025 年 11 月 1 日起，面向 Android 15+ 设备的应用更新必须支持 16 KB page size。这项变更对纯 Java/Kotlin 应用基本无感，真正的风险在 native 层：所有 .so 动态库都需要按 16 KB 对齐重新编译，只要有一个第三方 SDK 没跟上，应用在 16 KB 设备上就会直接崩溃。文章强调排查的难点在于依赖链的深度——很多 so 是通过闭源 SDK 间接引入的，需要用工具扫描 APK 内全部 native 库并逐一追溯供应方，建议尽早建立扫描脚本纳入 CI，而不是等发版被拒才排查。

### [Android 确定废弃「屏幕方向锁定」等 API，如何让 App 适配大屏和 PC/XR 场景](https://zhuanlan.zhihu.com/p/1889924505721348834)
**摘要**：文章分析 Google 从 Android 16 起逐步废弃用于限制应用屏幕方向的 manifest 属性与运行时 API 这一决定。背后的动机是设备形态的多元化——折叠屏、平板、桌面模式、XR 头显都需要应用能自适应任意尺寸与方向，而"锁死竖屏"的历史做法在这些场景下体验极差。文章给出的适配思路是从"锁定方向"转向"响应式布局"：用窗口尺寸类别（WindowSizeClass）驱动布局分支，把横竖屏当成连续的尺寸变化而非两种离散状态，并妥善处理配置变更下的状态保存。文章提醒这类改造往往牵涉面广，存量工程需要按页面优先级分批推进。
